# University Classroom Management Web API (ЛР №2 з МРПЗ)

> **Дисципліна:** Моделювання та розробка програмного забезпечення (МРПЗ)  
> **Тема:** Розробка Web API з використанням GitHub Copilot, модульного тестування та TDD.  
> **Основа:** Декомпозиція та задачі з Jira (ЛР №1, проєкт `КНРТ`).

---

## 📌 Опис проєкту
Система керування університетськими аудиторіями та їх бронюванням, розроблена на платформі **.NET 8 (C#)** із застосуванням методології **Test-Driven Development (TDD)**:
- **КНРТ-5:** Реєстрація нових аудиторій з валідацією місткості, номерів та обладнання.
- **КНРТ-4:** Пошук та фільтрація аудиторій за мінімальною місткістю, обладнанням (проектор, комп'ютери тощо) та корпусом.
- **КНРТ-16:** Бронювання аудиторій з алгоритмом запобігання перетинам та конфліктам часу (HTTP 409 Conflict).
- **КНРТ-22:** Архітектурна структура .NET Solution з розділенням Web API та тестового проєкту.

## 🚀 Швидкий запуск

### 1. Запуск модульних тестів (xUnit):
```bash
dotnet test
```
*Усі 29 модульних тестів виконуються в автоматичному режимі.*

### 2. Запуск Web API зі Swagger UI:
```bash
dotnet run --project ClassroomManagement.Api --launch-profile "http"
```
Після запуску відкрийте в браузері інтерактивну документацію:  
👉 **http://localhost:5031/swagger**

## 🧪 Методологія TDD (Red → Green → Refactor)
Розробка кожної вимоги відбувалася за циклом TDD:
1. 🔴 **Red:** написання модульного тесту на xUnit, що фіксує вимогу та падає до реалізації.
2. 🟢 **Green:** реалізація мінімально необхідного коду моделі, сервісу чи репозиторію до успішного проходження тесту.
3. 🔵 **Refactor:** оптимізація коду, структурування DTO та контролерів без порушення тестів.

## 📡 API Ендпоінти

| Метод | URL | Опис | Очікувані статус-коди |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/classrooms` | Додавання нової аудиторії | `201 Created`, `400 Bad Request` |
| `GET` | `/api/classrooms/{id}` | Отримання даних аудиторії | `200 OK`, `404 Not Found` |
| `GET` | `/api/classrooms/search` | Пошук аудиторій за місткістю та обладнанням | `200 OK` |
| `POST` | `/api/bookings` | Бронювання аудиторії з перевіркою конфліктів часу | `201 Created`, `400 Bad Request`, `404 Not Found`, `409 Conflict` |
| `GET` | `/api/bookings/{id}` | Отримання деталей бронювання | `200 OK`, `404 Not Found` |
| `GET` | `/api/bookings/classroom/{classroomId}` | Список усіх бронювань для аудиторії | `200 OK` |

## 🗂 Структура рішення

```text
ClassroomManagementSystem/
├── ClassroomManagement.Api/         # Проєкт Web API
│   ├── Controllers/                 # REST API Контролери
│   ├── DTOs/                        # Моделі передачі даних (Data Transfer Objects)
│   ├── Models/                      # Доменні сутності (Classroom, Booking)
│   ├── Repositories/                # Інтерфейси та потокобезпечне сховище
│   ├── Validators/                  # Бізнес-логіка перевірки та конфліктів часу
│   └── Program.cs                   # Налаштування DI контейнера та Swagger
├── ClassroomManagement.Tests/       # Проєкт модульного тестування (xUnit + FluentAssertions)
│   ├── ClassroomRegistrationTests.cs# Тести валідації реєстрації (КНРТ-10)
│   ├── ClassroomSearchTests.cs      # Тести фільтрів пошуку (КНРТ-14, КНРТ-15)
│   ├── BookingTests.cs              # Тести накладок та валідації часу (КНРТ-21)
│   ├── ClassroomControllerTests.cs  # Тести API контролера аудиторій
│   └── BookingsControllerTests.cs   # Тести API контролера бронювань
├── .vscode/                         # Налаштування запуску та дебагу у VS Code
├── ЗВІТ_ЛР2.md                      # Детальний звіт про виконання лабораторної роботи
└── ClassroomManagementSystem.sln    # Файл рішення .NET
```
